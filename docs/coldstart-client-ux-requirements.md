# 冷启动测速客户端 UX/UI 需求与开发计划

> 文档状态：**可开发需求稿 v1.0**  
> 审核对象：Electron 桌面客户端、浏览器备用模式、自动冷启动测速流程  
> 依据：当前分支 `scrcpy-frame-precision` 的实际代码、运行日志、Android 实机验证和 UX 审核结果  
> 目标：把当前“能用的工程工具”提升为“同事拿到即可完成一次完整测速”的桌面客户端。

---

## 1. 审核结论

当前技术路线正确，但当前使用体验**不是最佳**。

已经验证且应保留的核心设计：

- Electron 桌面客户端作为主要形态；
- 开跑前置检查清单；
- scrcpy 视频流优先、ADB 截图自动回退；
- 启动成功模板匹配；
- 自动循环执行首次/二次冷启动；
- 运行审计日志；
- 首次/二次分组统计与去极值；
- Excel 汇总和样本明细导出。

当前最影响使用的不是视觉细节，而是四个结构性问题：

1. Electron 中新建项目使用 `prompt()`，主客户端可能无响应；
2. 状态和错误大量写入隐藏的手动计时区域，用户看不到反馈；
3. 自动跑测期间设备、项目和操作按钮仍可修改，存在数据污染风险；
4. APK、模板、项目和启动模式之间的前置条件不够一致，失败往往发生在点击开始之后。

## 2. 产品目标

### 2.1 用户目标

目标用户无需阅读源代码或后端日志，就能完成：

```text
启动客户端
→ 连接手机
→ 创建/选择项目
→ 选择应用和 APK
→ 设置启动成功模板
→ 通过开跑检查
→ 开始自动循环
→ 查看表格化结果
→ 导出 Excel
```

### 2.2 体验目标

| 目标 | 验收标准 |
|---|---|
| 可发现 | 用户能在 30 秒内找到“连接设备、选择项目、开始测速”三个入口 |
| 可解释 | 所有失败必须在界面显示原因，不要求用户打开 DevTools 或终端 |
| 可防错 | 不满足必要条件时按钮禁用，并显示具体缺项 |
| 可恢复 | 视频流失败回退截图；APK 路径失效时可重新上传；旧模板不导致崩溃 |
| 可控 | 跑测中不能切换设备/项目/启动配置，停止时有明确进行中反馈 |
| 可读 | 报告默认显示摘要表，详细文字和审计日志折叠显示 |
| 可复现 | 项目保存模板、包名、启动方式和模板源分辨率；同一项目可以再次运行 |

## 3. 术语和状态

### 3.0 冷启动测速模式必须明确区分

客户端需要把以下两种测速模式明确展示给用户，不能只在审计日志中区分：

| 模式 | 帧源 | 典型截图/匹配耗时 | 结论含义 |
|---|---|---:|---|
| **高帧率视频测速** | scrcpy 4.0 H.264 视频流，默认 720 高度 | 帧龄约 16ms，匹配约 1–2ms | 当前新增的高帧率冷启动测速 |
| **ADB 截图回退测速** | `screencap \| gzip` / PNG | 通常约 300–500ms | 兼容/降级模式，不是高帧率结果 |

界面必须持续显示帧源徽章：

```text
高帧率视频 · 324×720
```

或：

```text
ADB 截图回退
```

报告和审计日志也必须记录本轮实际帧源。若同一轮中途发生回退，报告应显示：

```text
帧源：视频流（部分样本回退 ADB 截图）
```

不能把 ADB 回退样本与全程高帧率样本混称为“高帧率测速”。

### 3.0.1 高帧率模式前置条件

只有同时满足以下条件才允许标记为高帧率视频测速：

- `stream_status.available == true`；
- scrcpy 视频流握手完成；
- 模板源分辨率与视频帧分辨率一致；
- 本轮命中样本的 `shot_via == "video"`；
- 无视频断流或回退记录。

否则显示“ADB 截图回退”或“混合帧源”，不显示“高帧率视频测速”。


### 3.1 主要状态

客户端需要统一使用以下状态，不允许同一含义出现多套文案：

| 状态 | 含义 | 用户可见文案示例 |
|---|---|---|
| `idle` | 未连接设备或未开始配置 | 等待连接设备 |
| `preparing` | 正在启动后端/建立视频流/加载项目 | 正在准备测速环境 |
| `ready` | 设备、APK、包名、模板均满足要求 | 可以开始自动循环 |
| `running` | 自动循环正在执行 | 第 2/5 轮 · 首次冷启动 |
| `stopping` | 用户已点击停止，但当前 ADB 操作尚未结束 | 正在停止当前步骤… |
| `success` | 当前步骤或本轮成功 | 首次冷启动完成 · 5.350s |
| `warning` | 可继续但需要用户注意 | 视频流不可用，已回退 ADB 截图 |
| `error` | 当前操作失败 | 自动循环已中止：安装失败 |

### 3.2 测速状态

后端现有状态机继续保留：

```text
cold_start
→ 设备启动
→ 跳过弹窗（首次可选）
→ 启动成功模板识别
→ 上升沿确认
→ 记录首次/二次样本
→ 生成报告
```

本需求不改变停表语义：

- 视频路径使用主机 `received_at` 对应帧；
- ADB 路径使用现有 `shot_ms` 补偿；
- `pts` 仅用于视频诊断，不作为跨设备主计时钟。

## 4. 必须开发项（P0）

## P0-1 Electron 新建项目输入

### 当前问题

`static/index.html` 使用浏览器 `prompt()` 创建项目。Electron 主客户端中可能无输入框或静默返回空值，导致点击“新建项目”无反应。

### 需求

实现统一的 `uiPrompt()`：

- Electron 和浏览器均可使用；
- 支持标题、说明、默认值、确认、取消；
- Enter 确认，Esc 取消；
- 输入为空时提示“项目名称不能为空”；
- 名称长度限制与后端一致；
- 不允许通过 HTML 拼接未转义用户输入。

### 推荐实现

优先使用前端内嵌 Modal，不新增 BrowserWindow：

```text
uiPrompt(title, detail, defaultValue)
→ Promise<string | null>
```

这样可以统一处理：

- 新建项目；
- 项目重命名；
- 未来可能的模板命名。

### 验收

- Electron 中点击“新建项目”出现输入框；
- 输入合法名称后项目创建成功并自动选中；
- 取消不产生请求；
- 空名称不会调用后端；
- 浏览器模式行为一致。

---

## P0-2 跑测期间锁定界面，保护数据完整性

### 当前问题

自动循环期间仍可切换设备、项目、包名、启动方式、模板、截图、OCR、重装和快捷键，可能导致样本写入错误项目或测到另一台设备。

### 需求

`setAutoRunLayout(true)` 时锁定：

- 设备选择和刷新；
- 项目选择、新建、保存、删除、重命名；
- 启动方式、包名、坐标；
- APK 上传、卸载重装、杀进程、回主页；
- 手动截图、OCR、模板设置和跳过模板操作；
- 直播开关；
- 删除历史样本、清空记录；
- `Q/W/R/Delete` 等可能影响设备或数据的快捷键。

保留可用：

- 停止按钮；
- 复制当前日志；
- 查看当前报告；
- 展开/收起审计日志。

### 停止反馈

点击停止后：

```text
停止按钮 → “停止中…” → 当前 ADB 操作结束 → 清理状态 → 恢复控件
```

不能点击后立即变成普通禁用状态，让用户误以为客户端卡死。

### 断连自动中止

`waitForLaunchDone` 需要统计连续设备错误：

- 连续 3 次：显示警告；
- 连续 8 次或持续约 5 秒：自动中止本轮；
- 报告记录明确原因：设备断开/视频流不可用/ADB 失败；
- 不允许无限循环 WARN。

### 验收

- 跑测中切换设备按钮不可用；
- 跑测中切换项目不会改变当前记录桶；
- 跑测中 Delete/Q/W 不会修改数据或设备；
- 设备断开后在有限时间内自动停止并显示原因；
- 停止操作最终可以恢复界面。

## P0-3 全局可见状态反馈

### 当前问题

`setState()` 主要更新隐藏的手动计时区域，用户看不到设置坐标、杀进程失败、模板失败或自动循环中止等状态。

### 需求

增加常显状态条，建议放在自动测速卡片顶部：

```text
[● 已连接] Pixel 6a · 视频流 324×720 · 58fps
```

状态条至少显示：

- 当前设备；
- Android/iOS 平台；
- 后端状态；
- 视频流/ADB 截图帧源；
- 当前操作状态；
- 最近错误或警告。

`setState(kind, text)` 同时更新：

1. 状态条；
2. 当前卡片状态；
3. 审计日志（需要时）。

### 错误反馈格式

统一显示：

```text
操作失败（HTTP 400）：包名启动失败：找不到可启动的 Activity
```

禁止只显示：

```text
请求失败
```

### 验收

- 设置坐标后有可见提示；
- 设置模板成功/失败有可见提示；
- APK 上传失败有可见提示；
- `cold_start` 400 显示后端 detail；
- 自动循环中止原因显示在状态条和报告摘要中。

## P0-4 开跑前置条件统一

### 必选条件

Android 包名启动模式：

- 设备已连接；
- 包名已填写；
- APK 文件路径非空且后端确认文件存在；
- 启动成功模板已设置；
- 当前项目配置有效；
- 不在另一个测速循环中。

模拟点击模式额外要求：

- `tapX` 和 `tapY` 均为合法数值，包括 `0` 坐标；
- 当前设备画面已更新。

### APK 检查

前端开跑清单不能只检查字符串非空：

```text
输入框有路径 ≠ 文件真实存在
```

增加轻量接口或复用 `preflight_auto`，在用户点击开始前显示：

```text
✓ APK 文件存在 · 200.1 MB
```

如果不存在：

```text
✗ APK 文件已失效，请重新上传
```

### 项目切换

切换项目时：

- 默认不清空当前 APK 路径；
- 如果路径仍存在，保留并显示“沿用本机 APK”；
- 如果路径不存在，才清空并提示重新上传；
- 项目仍不保存 APK 本体，只保存 `apk_hint`。

## 5. 重要功能优化（P1）

## P1-1 测试模式选择

在自动循环区域增加：

```text
测试模式：
○ 完整循环（首次 + 二次）
○ 仅二次冷启动
○ 单次冷启动
```

行为：

| 模式 | 卸载重装 | 首次 | 二次 |
|---|---:|---:|---:|
| 完整循环 | 是 | 是 | 是 |
| 仅二次 | 否 | 否 | 是 |
| 单次首次 | 可选 | 是 | 否 |
| 单次二次 | 否 | 否 | 是 |

默认仍为“完整循环”，保证现有用户行为不变。

## P1-2 报告表格化

报告默认显示摘要表，不直接展示整段审计日志。

### 默认摘要表

| 类型 | 样本数 | 原始均值 | 剔除极值 | 去极值最终值 | 状态 |
|---|---:|---:|---|---:|---|
| 首次冷启动 | 5 |  | MAX/MIN |  | 有效 |
| 二次冷启动 | 5 |  | MAX/MIN |  | 有效 |

规则：

- `n >= 3`：去掉 1 个最大值和 1 个最小值；
- `n < 3`：全量平均并标记“样本不足，未剔除”；
- 异常样本单独显示；
- 详细文字报告和审计日志放入折叠区域；
- Excel 输出“报告汇总”和“样本明细”两个工作表。

## P1-3 模板操作文案

明确区分三种点击行为：

```text
直接点画面：设置应用图标坐标
点击“设置启动成功模板”后再点画面：截取启动成功模板
点击“添加跳过按钮”后再点画面：截取跳过模板
```

设置模板后展示：

- 模板预览；
- 模板宽高；
- 源画面分辨率；
- 来源：视频帧 / ADB 截图；
- 与当前视频流是否匹配。

## P1-4 项目和 APK 复用

项目保存：

- 包名；
- 启动方式；
- 点击坐标；
- marker 模板；
- skip 模板；
- 模板源分辨率；
- APK 文件名提示，不保存 APK 本体。

加载项目时：

- 如果 APK 路径仍有效，自动复用；
- 否则显示明确的重新上传按钮；
- 不把路径非空误显示为“已准备好”。

## 6. iOS 体验范围

当前 iOS 入口属于部分实现，不能继续伪装成完整 Android 同等流程。

### 本期最小要求

切换到 iOS 时：

- 上传控件接受 `.ipa`；
- 隐藏或禁用模拟点击；
- 隐藏 Android 包名启动提示；
- 隐藏 Android force-stop、回主页、kill-all 按钮；
- 开跑清单显示 iOS 专用要求；
- 明确提示 iOS 无 scrcpy 高帧率视频路径；
- 报告显示 iOS 平台调整规则。

如果本期不开发完整 iOS 流程，应将平台标签改为：

```text
iOS（实验功能）
```

避免误导用户。

## 7. 视觉设计规范

### 7.1 保留

- 当前三栏 Studio 布局；
- 暗色主题；
- 卡片分组；
- 绿色/黄色/红色状态色；
- 运行审计日志；
- 自动测速报告卡片。

### 7.2 调整

- 状态色必须同时配合文字，不只依赖颜色；
- 最小正文/标签字号不低于 11px；
- 所有删除按钮增加 `title` 和 `aria-label`；
- 所有可操作控件增加明确的 `:focus-visible` 样式；
- 亮色主题重新校准 primary/warning 对比度；
- 统一面板与按钮圆角 token；
- 跑测中禁用控件应使用低对比但仍可读的状态，不只设置 `opacity: 0.4`。

### 7.3 信息层级

优先级从高到低：

```text
当前状态/错误
→ 当前轮次和测量结果
→ 开跑条件
→ 配置参数
→ 详细日志
→ 历史数据
```

## 11. 开发完成定义（Definition of Done）

满足以下条件才算本需求完成：

- Electron 可新建项目；
- APK 原生选择和上传可用；
- 跑测期间不可修改设备和项目；
- 错误在界面可见且包含原因；
- 完整、单次、仅二次模式按设计工作；
- 视频流可用时 `shot_via=video`；
- 视频流不可用时自动回退 ADB；
- 模板分辨率不匹配不会崩溃或误匹配；
- 报告默认显示摘要表；
- 去极值平均值在表格中清楚展示；
- Excel 文件可在 Excel/WPS 中打开；
- 所有现有测试通过；
- Windows 打包验证通过；
- macOS 实机验证完成或明确标记为后续发布项。

## 12. 推荐开发顺序

```text
Sprint 1 防错和反馈
    ↓
Sprint 2 测试模式与报告
    ↓
Windows 打包验证
    ↓
macOS 实机验证
    ↓
Sprint 3 iOS/视觉打磨
```

优先修复“项目建不了、看不到错误、跑测可被干扰”三个问题，再进行颜色、圆角和动画等视觉打磨。
