## 目标

把 OCR 自动停表的"全屏 OCR 文字匹配"（秒级，精度差）升级为"小区域模板图比对"（毫秒级，精度高），让轮询间隔能真正降到 50-100ms，冷启动计时精度从 ±1-2s 提升到 ±50ms。

## 核心方案：区域 + 模板图比对（cv2.matchTemplate）

**用户操作**（一次性配置）：
1. 手动启动 App 到首页（让"启动成功"元素出现在画面上）
2. 点 OCR 框或点画面，选定"启动成功"元素的位置
3. 后端自动以该坐标为中心截取一个小区域（如 240×120 像素），存为模板图

**运行时**（每次轮询）：
1. 后端截当前屏幕
2. 用 cv2.matchTemplate 在"模板坐标周围一定范围"搜索（处理元素轻微位移/抖动）
3. 置信度超阈值（默认 0.85）即判定启动成功，返回命中时刻
4. 整个过程 ~20-50ms（vs 当前全屏 OCR 800-2000ms）

**性能对比**：
| 方案 | 单次轮询 | 停表精度 | 可靠性 |
|---|---|---|---|
| 当前：全屏 OCR 文字匹配 | 800-2000ms | ±1-2s | 中（OCR 偶尔漏识） |
| 新：区域模板比对 | 20-50ms | ±50ms | 高（像素级匹配） |

## 改动一：后端新增「设为启动模板」端点（server.py）

```python
@app.post("/api/set_marker_template")
def set_marker_template(req: SetMarkerReq) -> dict:
    """以当前屏幕上 (cx, cy) 为中心截取一个小区域，存为启动成功模板。
    
    模板存到 APK_UPLOAD_DIR 同级的 _cst_marker.png（单文件，覆盖式）。
    返回模板信息（尺寸/预览 base64），前端可显示让用户确认截对了。
    """
```

请求字段（**只新增端点，不动现有端点**）：
- `cx`, `cy`：归一化坐标（0~1），来自用户点 OCR 框或点画面
- `box_w`, `box_h`：可选，若来自 OCR 框就用框的尺寸；否则用默认 240×120

实现：
- 截当前屏幕
- 按 cx/cy 计算像素中心，取小区域（保证不越界）
- 存到 `tempdir/_cst_marker.png`
- 返回 `{ok, width, height, preview_base64}`（preview 让前端显示缩略图确认）

## 改动二：后端新增「检测模板命中」端点（server.py）

```python
@app.get("/api/check_marker")
def check_marker() -> dict:
    """截当前屏 + 在模板坐标周围搜索模板，返回是否命中 + 置信度。
    
    搜索范围：模板位置 ± 20 像素（处理 UI 轻微抖动）
    匹配方法：cv2.TM_CCOEFF_NORMED（归一化相关系数，最鲁棒）
    阈值：0.85（可调）
    """
```

返回：`{hit: bool, confidence: float, ms: float}`（ms 是本次检测耗时，前端诊断用）

**关键设计**：
- 每次调用都重新截图（不复用截图缓存，避免错过关键帧）
- 搜索范围小（只搜模板周边），所以快
- 不需要前端传坐标（坐标在 set_marker_template 时已记录在后端 session 里）

**Session 扩展**（只加字段，不改现有）：
```python
class Session:
    # 新增字段
    self._marker_template: Optional[Path] = None    # 模板图路径
    self._marker_cx: float = 0.5                     # 模板中心归一化坐标
    self._marker_cy: float = 0.5
```

## 改动三：前端 UI 改造（index.html）

**自动测速卡片新增「启动标识」配置区**（两种模式二选一）：

```
启动成功检测：
  ○ 文字匹配（OCR，慢，~1s/次）   ← 老模式保留
  ● 模板比对（点画面定位，快，~50ms/次）  ← 新模式默认

模板设置：
```

**两种模式并存**：用户可选文字匹配或模板比对。默认推荐模板比对（快）。

**选定流程**：
1. 用户点「点画面选定启动元素」按钮 → 进入选定模式（鼠标变十字）
2. 用户点画面上的"启动成功"元素（或点 OCR 框）
3. 前端调 `/api/set_marker_template {cx, cy}`
4. 后端截图存模板，返回预览
5. 前端显示模板缩略图 + 尺寸，用户确认

## 改动四：前端 waitForOcrMarker 升级（index.html）

改名为 `waitForLaunchDone`，根据模式分流：

```javascript
async function waitForLaunchDone(startTs, mode, marker, timeoutMs, gapMs) {
  while (true) {
    if (autoAbortFlag) throw new Error('用户中断');
    if (performance.now() - startTs > timeoutMs) throw new Error('超时');
    
    let hit = false;
    if (mode === 'template') {
      // 新：调 check_marker，毫秒级
      const r = await fetch(API + '/api/check_marker');
      const j = await r.json();
      hit = j.hit;
    } else {
      // 老：调 ocr，秒级
      const r = await fetch(API + '/api/ocr');
      const j = await r.json();
      hit = ocrHitSuccessMarker(j, marker);
    }
    
    if (hit) return performance.now() - startTs;
    await sleep(gapMs);
  }
}
```

runAutoLoop 调用方相应改造，根据单选框选 mode。

## 风险与取舍

- **cv2 已装**（现有 OCR 已用），不引入新依赖 ✓
- **模板坐标漂移**：UI 元素可能因状态栏隐藏/动画轻微位移。解法：search_range ±20px 容忍小位移；若仍漂移，用户重新选定
- **首次截图延迟**：set_marker_template 时截的图 vs 运行时的图，分辨率/方向必须一致（同设备同方向，正常情况一致）
- **文字匹配保留**：模板比对失败时（极端情况），用户可切回文字匹配降级
- **模板文件清理**：每次 set 覆盖，startup 清理（与 _cst_uploads 一起）
- **冷启动首帧可能是黑屏/闪屏**：模板比对的是"启动成功"那帧的特征，黑屏阶段置信度天然低于阈值，不会误触发 ✓
